# Security findings matrix

These findings describe the intentionally vulnerable lab build. No severity labels are assigned: the values and service are synthetic, so real-world impact depends on the sensitivity and privileges of data in an actual application.

| ID | Category | Component | Discovery | Evidence | Exploitability considerations | Impact in this lab | Remediation | Demo priority |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| A | Hardcoded client credential | React Native bundle / lab support API | JADX bundled JS string search | `SC-LAB-PRIV-4D92A7` calls `/api/lab/support-info` and returns a synthetic note | Requires APK access; a shared client key is recoverable and reusable | Reveals only fictional help text | Do not embed privileged secrets in clients; authenticate and authorize on the server | Core |
| B | Broken object-level authorization | Express account and history routes | Change `accountId` in authenticated request | Ada's bearer token gets Grace's seeded account in vulnerable mode; corrected mode returns 403 | Valid session plus a known/guessable identifier | Cross-account synthetic balance and history disclosure | Check account ownership on every server request | Core |
| C | Cleartext transport | Android network policy and local API | Inspect XML/manifest, then capture emulator HTTP | Account demo response travels over HTTP | Attacker needs a position to observe or alter the lab link | Synthetic data can be observed in the controlled capture | Enforce HTTPS with trusted certificates outside the lab | Core |
| D | Insecure local storage | React Native AsyncStorage | Inspect source and app-private database on a controlled emulator | `insecurebank.session` is persisted by AsyncStorage | Reading app-private storage normally requires app/device access; rooted/debuggable contexts change that boundary | A session token can be recovered from the lab app's private data | Minimize persistence; use Keystore-backed encrypted storage for a real app and short-lived, revocable tokens | Optional |
| E | Sensitive information in logs | Login handler | Trigger login and filter Android logs | Synthetic bearer token is written at `[EXERCISE E]` | Log access depends on Android version, device state, build, and permissions | The lab session may be exposed to a log reader | Remove secrets and payloads from logs; log an event identifier only | Optional |
| G | Mistaking `.env` for a client-side secret store | Mobile bundle config | Search the APK bundle for the fake env value | The fake value appears in the bundled client | Inspectors control the client and can recover bundled values | A client value can be copied from the APK | Keep secrets server-side; bundle only public configuration | Optional |
| F | Exported component exposure | Not implemented | Not applicable | No custom externally callable component is added | Exported alone does not establish an authorization flaw | None | Evaluate permissions, input validation, and authorization for each component | Omitted |
